🎨 Arbeiten mit Dreamweaver

Automatisch ignorierte Dateien

Folgende Dateien werden von Git automatisch ignoriert (.gitignore):

Dateityp Beschreibung Aktion
_notes/ Dreamweaver Notizen & Metadaten Ignorieren
*.dwt Dreamweaver Templates Ignorieren
*.bak Backup-Dateien Ignorieren
dwsync.xml Synchronisierungs-Meta Ignorieren
💡 Hinweis: Diese Dateien werden automatisch von Git ignoriert. Du brauchst dir keine Sorgen zu machen, dass sie committed werden.

Vor der Arbeit

  • ✅ Git Pull machen: Neue Änderungen vom Server abrufen
  • ✅ Lokale Änderungen committen: Sicherstellen, dass alles gespeichert ist
  • ✅ Synchronisierung deaktivieren: Falls Dreamweaver Auto-Sync hat
git pull origin main

Während der Arbeit

  • 🔍 Links lokal testen
  • 🎯 HTML/CSS validieren
  • 💾 Regelmäßig speichern
  • 🚫 Keine externen Links hard-coden

🔄 Git Workflow

Einfacher Workflow (für kleine Änderungen)

git add .
git commit -m "docs: Updated service pages"
git push origin main

Feature-Branch Workflow (empfohlen)

# Neuen Feature-Branch erstellen
git checkout -b feature/update-galerie

# ... Arbeit in Dreamweaver ...

# Änderungen committen
git add .
git commit -m "feat: Add new gallery items"

# Zurück zu main
git checkout main

# Feature mergen
git merge feature/update-galerie

# Zum Server pushen
git push origin main
✨ Best Practice: Verwende Feature-Branches für größere Änderungen. So bleibt der main-Branch immer stabil.

Konflikt vermeiden

  • Immer git pull machen vor der Arbeit
  • Regelmäßig pushen (nicht zu lange lokal arbeiten)
  • Mit anderen Entwicklern kommunizieren

📝 Commit-Messages

Commit-Typ Schema

Verwende folgendes Format für aussagekräftige Commit-Messages:

Typ Beschreibung Beispiel
feat: Neue Features/Funktionalität feat: Add contact form validation
fix: Bugfixes fix: Correct typos in impressum
docs: Dokumentation & README docs: Update development guide
style: HTML/CSS Styling (keine Logik) style: Update CSS for responsive design
refactor: Code-Umstrukturierung refactor: Reorganize CSS structure
chore: Build-Tools, Versionierung chore: Release v1.1.0

Gute vs. Schlechte Messages

✅ Gut: 
git commit -m "feat: Add responsive navigation menu"
git commit -m "fix: Correct gallery image padding"
git commit -m "docs: Add developer guidelines"
❌ Schlecht: 
git commit -m "Update"
git commit -m "Fixed stuff"
git commit -m "Work in progress"

📦 Versionierung & Releases

Semantische Versionierung (SemVer)

Format: MAJOR.MINOR.PATCH (z.B. 1.2.3)

  • MAJOR (1.x.x): Inkompatible API-Änderungen
  • MINOR (x.1.x): Neue Funktionalität, abwärtskompatibel
  • PATCH (x.x.1): Bugfixes und kleine Verbesserungen

Version & Changelog aktualisieren

# 1. Version in package.json erhöhen (z.B. 1.0.0 → 1.1.0)
# 2. Änderungen in CHANGELOG.md dokumentieren
# 3. Committen
git add package.json CHANGELOG.md
git commit -m "chore: Release v1.1.0"

# 4. Git Tag erstellen
git tag -a v1.1.0 -m "Release version 1.1.0"

# 5. Zum Server pushen (inklusive Tags)
git push origin main --tags
📖 Weitere Infos: Siehe CHANGELOG.md und package.json für aktuelle Version und Historie.

✅ Entwickler Checkliste

Vor dem Pushen

  • Alle Änderungen lokal getestet
  • Alle Links funktionieren korrekt
  • CSS & JavaScript laden ordnungsgemäß
  • Keine sensiblen Daten in Code
  • Commit-Message ist beschreibend
  • git status zeigt erwartete Dateien
  • Keine großen Binärdateien committed

Daily-Standup (optional)

# Morgens: Neuste Änderungen abrufen
git pull origin main

# Abends: Änderungen committen & pushen
git add .
git commit -m "docs: End of day updates"
git push origin main

Nützliche Git-Befehle

Befehl Beschreibung
git status Status aktueller Änderungen anzeigen
git log --oneline -5 Letzten 5 Commits anzeigen
git diff Unterschiede seit letztem Commit
git restore [datei] Datei auf letzten Commit zurücksetzen
git tag -l Alle Versions-Tags anzeigen

⚠️ Häufige Probleme & Lösungen

Merge Conflicts

Problem: Git kann Änderungen nicht automatisch mergen.

Lösung: Immer git pull machen vor Änderungen. Im Konfliktfall die Datei manuell bearbeiten und erneut committen.

Versehentliches Committen von Dreamweaver-Dateien

Problem: _notes/ oder .bak Dateien committed.

Lösung: Die .gitignore ist bereits konfiguriert. Falls es passiert: git rm --cached [datei] nutzen.

Zu viele Dateien auf einmal committed

Problem: Mit git add . werden alle Dateien hinzugefügt.

Lösung: Selektiv committen: git add [spezifische-datei]
